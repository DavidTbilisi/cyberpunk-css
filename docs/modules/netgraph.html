NetGraph module

Built-in SVG: scripts/netgraph.js · scss/_netgraph.scss. Optional library view: scripts/netgraph-vis.js · scss/_netgraph-vis.scss (both composed from scss/cyberpunk.scss).

Purpose

NetGraph renders a read-only SVG diagram of a small network: nodes (hosts, routers, servers) on a ring layout and directed edges from source to target. It is meant for dashboards and demos, not graph editing.

The canvas uses a large internal coordinate system (default 1200×560) so labels and nodes stay legible; the SVG scales with the container. Optional packet dots animate along edges in the same direction as the arrows.

Flow direction

  • Topology — Each edge is { source: 'idA', target: 'idB' }. Traffic in the demo is shown from A → B.
  • Arrows — By default, each edge is an SVG <line> with marker-end pointing at the target node. Lines are shortened so arrows sit outside the node discs.
  • Packets — When enabled, animated circles move from the trimmed start of the line to the trimmed end (same as arrow direction).
  • Disable cues — Set arrows: false for undirected diagrams, or packets: false for a static graph.

API

renderNetGraph(container, topology?, options?) → { destroy }

  • container — CSS selector string or DOM element.
  • topology — Object with nodes and edges (see below).
  • options — Optional settings (see table).
  • Returns { destroy }. Calling destroy() clears timers and DOM. Rendering again into the same container automatically tears down the previous graph.

initNetGraph() — Wires buttons with data-netgraph-load. Runs on DOMContentLoaded when the script loads. Each click calls renderNetGraph on the target element.

Topology format

{
  "nodes": [
    { "id": "gw", "label": "Gateway", "type": "router" },
    { "id": "app", "label": "App", "type": "server" },
    { "id": "c1", "label": "Client", "type": "client" }
  ],
  "edges": [
    { "source": "gw", "target": "app" },
    { "source": "c1", "target": "gw" }
  ]
}

Fields:

  • nodes[].id — Required string key referenced by edges.
  • nodes[].label — Optional; falls back to id.
  • nodes[].type — "router" | "server" | anything else (treated as client/worker) — controls disc size and color.
  • edges[].source / edges[].target — Must match existing node ids. Invalid edges are skipped.

Custom x / y on nodes are not used yet; layout is a balanced ring inside the view box.

HTML-only and Mermaid-like text (recommended for authors)

scripts/netgraph-markup.js (loaded from scripts/init.js) turns declarative markup into the same topology object renderNetGraph already understands. You avoid hand-writing JSON in attributes.

Option A — Mermaid-inspired <script type="text/cp-netgraph">

One block of plain text (similar spirit to Mermaid flowcharts, but not full Mermaid syntax):

  • Nodes — id(Label) or id[Label], optional type: id(Label):::router / :::server / :::node (aliases: r, s, srv, db for server).
  • Edges — from --> to or from -> to (one edge per line).
  • Comments — lines starting with # are ignored.

Option B — Pure HTML lists

Inside the same definition root, omit the script and use:

  • A container data-netgraph-nodes with descendants carrying data-id, optional data-type, and text content as the label.
  • A container data-netgraph-edges with descendants carrying data-from and data-to.

Manual trigger: a button with data-netgraph-build and data-netgraph-from="#id-of-def" (the definition root must still include data-netgraph-target).

<div id="net-def" hidden

  data-netgraph-auto
  data-netgraph-target="#net-viz"
  data-netgraph-title="LAN">

n1(Node 1)
db(DB):::server

gw --> n1
gw --> db

  </script>
</div>

Optional: vis-network (npm install vis-network)

For interactive graphs (drag nodes, zoom, physics), use the separate module scripts/netgraph-vis.js. It is not imported from scripts/init.js, so the default demo stays lightweight. The library loads only when you import() this file in the browser.

  • Dependency — vis-network is listed in package.json. The standalone ESM bundle is resolved from node_modules/vis-network/standalone/esm/vis-network.js relative to the script URL, so your static server must expose node_modules (typical for local dev).
  • Styles — On first render, a <link> is injected for vis-network/styles/vis-network.min.css. Panel chrome uses .cp-netgraph--vis and .cp-netgraph-vis__canvas.
  • Topology — Same nodes / edges schema as the SVG renderer. Plain mapping lives in scripts/netgraph-vis-topology.js (topologyToVisElements) for unit tests without loading vis.
  • Theme colors — Same semantics as the SVG graph: router = --cp-magenta, server = --cp-blue, other = --cp-cyan; borders mix --cp-foreground, highlights use --cp-amber, edges tint --cp-cyan. renderNetGraphVis passes the mount element as themeRoot so getComputedStyle picks up inherited tokens (e.g. a parent with class="theme-matrix"). If you call topologyToVisElements() yourself, pass { themeRoot: yourContainer } to match that subtree.
  • Flow — Edges use vis arrows to (target). Disable with arrows: false.

renderNetGraphVis(container, topology?, options?) — async; resolves to an object with destroy and network, or null on failure.

  • network — The vis Network instance for advanced callers (setData, event listeners, etc.).
  • Returns null if the container is missing or the vis module fails to load (check the console).
  • Uses the same __cpNetGraphDestroy hook as the SVG graph so you can swap implementations in one mount point.

Extra options (in addition to title and arrows):

import { renderNetGraphVis, topologyToVisElements } from './scripts/netgraph-vis.js';

const topology = { nodes: [...], edges: [...] };
const handle = await renderNetGraphVis('#host', topology, {
  title: 'Operations graph',
  visOptions: { physics: { barnesHut: { springLength: 260 } } }
});
// handle.network.on('click', ...);
// handle.destroy();

Declarative hook (data-*)

<button type="button" class="cp-btn"
  data-netgraph-load
  data-netgraph-target="#my-graph"
  data-netgraph-payload='{"nodes":[...],"edges":[...]}'>
  Load graph
</button>
<div id="my-graph"></div>
  • data-netgraph-target — Selector for the mount point (default #demo-netgraph if omitted).
  • data-netgraph-payload — Optional JSON string for topology; if missing or invalid, a built-in sample topology is used.

Options

Example (module)

import { renderNetGraph } from './scripts/netgraph.js';

const topology = { nodes: [...], edges: [...] };
const handle = renderNetGraph('#graph', topology, {
  title: 'Edge site',
  emitInterval: 1100,
  arrows: true,
  packets: true
});
// later: handle.destroy();

Styling

The root gets .cp-netgraph. The plot area is .cp-netgraph__canvas (responsive height via CSS clamp / min). Edge strokes and arrow fill use semi-transparent colors; override in your stylesheet with .cp-netgraph__edge and .cp-netgraph__arrow-head if needed.
